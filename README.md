# Jarvis — локальный голосовой ассистент

Полностью локальный голосовой ассистент для Windows 11 с кодовой фразой
**"Хей, Джарвис" (hey jarvis)**. Русская речь, локальная LLM через Ollama,
белый список безопасных действий. Подробности — в `spec.md` и `plan.md`.

> Изначально планировалось голое "Jarvis" через Picovoice Porcupine, но
> бесплатный тариф Porcupine закрылся 30.06.2026 (см. `RESEARCH.md`). Заменён
> на open-source openWakeWord с готовой моделью `hey_jarvis` — она надёжно
> триггерится именно на фразу "hey jarvis", а не на одиночное "Jarvis".

## 1. Что поставить руками

1. **Python 3.11+** — установить, добавить в PATH (нужны и `python.exe`, и
   `pythonw.exe` рядом с ним — это стандартно для официального инсталлятора).
2. **Зависимости проекта**:
   ```powershell
   cd "D:\claude code prj\3\jarvis"
   python -m venv .venv
   .venv\Scripts\activate
   pip install -r requirements.txt
   ```
   Виртуальное окружение и все модели/кэши держим на диске D — на диске C
   мало места.
3. **Wake word — ничего получать не нужно.** Используется open-source
   openWakeWord, без access key/регистрации. При первом запуске он сам
   скачает веса модели `hey_jarvis` (нужен интернет один раз).
4. **Ollama** — должен быть установлен и запущен (`ollama serve`).
   Уже стоят `gemma4:2b`, `gemma4:26b`, `nomic-embed-text` — этого мало,
   нужно ещё поставить основную модель для диалога/tool-calling:
   ```powershell
   ollama pull qwen3:8b
   ```
   (уже прописана в `config/config.yaml`; `gemma4:26b` остаётся как
   режим "глубокого анализа" по явной команде).

   Сейчас модели Ollama лежат на диске C (`%USERPROFILE%\.ollama\models`),
   а свободного места там мало. Чтобы перенести их на диск D (сделать один
   раз, до `ollama pull qwen3:8b`):
   ```powershell
   # Закрыть Ollama (иконка в трее -> Quit Ollama, либо):
   Stop-Process -Name "ollama","ollama app" -ErrorAction SilentlyContinue

   New-Item -ItemType Directory -Force -Path "D:\ollama-models" | Out-Null
   Move-Item "$env:USERPROFILE\.ollama\models\*" "D:\ollama-models\"
   [Environment]::SetEnvironmentVariable("OLLAMA_MODELS", "D:\ollama-models", "User")

   # Открыть Ollama заново, затем проверить, что старые модели видны:
   & "$env:LOCALAPPDATA\Programs\Ollama\ollama.exe" list
   ```
   Если после переноса `ollama list` не видит старые модели — они остались
   в `%USERPROFILE%\.ollama\models` (перенос не удался); тогда откатите
   переменную окружения и разбирайтесь перед тем как качать новую модель.
5. **faster-whisper / Silero** — тянутся автоматически через
   `requirements.txt`; веса моделей при первом запуске скачаются в кэш
   (по умолчанию в профиль пользователя — при нехватке места на C
   переопределите `HF_HOME`/`XDG_CACHE_HOME` на путь на диске D).

## 2. Запуск вручную (для теста)

### GUI-интерфейс (рекомендуется)
Запускает графическое окно с историей диалога, полем ввода текста и кнопкой микрофона:
```powershell
python gui.py
```
В этом режиме вы можете:
- Печатать сообщения в поле ввода и отправлять их (Enter или кнопка "➤")
- Нажать кнопку 🎤 для голосового ввода (скажите фразу, запись остановится автоматически после паузы)
- Видеть историю переписки в виде пузырьков сообщений
- Наблюдать текущий статус: "Ожидание", "Слушает", "Думает", "Говорит"

### Консольный режим
```powershell
cd "D:\claude code prj\3\jarvis"
.venv\Scripts\activate
python orchestrator.py
```

Есть также текстовый fallback-режим без микрофона/трея/тяжёлых ML-зависимостей
(нужны только `requests`+`PyYAML`) — удобно для быстрой проверки brain/tools:
```powershell
python orchestrator.py --text
```

При старте голосового режима появится иконка в системном трее (серый круг —
сон, ожидание фразы). Активировать можно двумя способами:
- Голосом: скажите **"Хей, Джарвис"**.
- **Клавишей Numpad "+"** — работает глобально, даже когда окно Jarvis не в
  фокусе. Полезно как запасной вариант, пока голос не настроен/барахлит
  (см. `config/config.yaml -> hotkey.key`, если хотите другую клавишу).

- **Текстом прямо в этой консоли** — просто напечатайте команду и нажмите
  Enter, без голоса и без клавиши. Работает одновременно с голосом/хоткеем,
  ничего переключать не нужно — удобно как временная страховка, пока
  разбираетесь, почему не срабатывает голос.

После активации любым способом — иконка станет зелёной (слушаю; для
текстового ввода — сразу переходит к ответу), после записи команды — жёлтой
(думаю), затем прозвучит голосовой ответ. Повторите активацию (голосом,
клавишей или текстом) ещё раз во время ответа — воспроизведение сразу
остановится (barge-in), можно сразу отдавать новую команду.

**Как понять, что Jarvis реально запустился и слушает** (а не тихо упал в
фоновом потоке): при старте должен прозвучать короткий двухтональный сигнал
"готовности" (после того как загрузится модель распознавания голоса и
откроется микрофон). Если сигнала нет — смотрите `logs/action.log`, там
будет явная причина (обычно: не установлен пакет, не скачаны веса модели,
нет доступа к микрофону/клавиатуре).

Правой кнопкой по иконке в трее:
- **Выключить** — останавливает ассистента.
- **Перезапустить** — перезапускает процесс.

Остановить из консоли — `Ctrl+C` в окне, где запущен `orchestrator.py`.

## 3. Автозапуск при входе в систему

Регистрирует задачу в Планировщике заданий Windows (без окна консоли,
автоматический перезапуск при сбое: через 1 минуту, до 3 попыток):

```powershell
cd "D:\claude code prj\3\jarvis"
service\autostart.ps1
```

Скрипт идемпотентен — повторный запуск не создаёт дублей задачи, а
переписывает существующую ("JarvisAssistant").

Запустить задачу сразу, не перезаходя в систему:
```powershell
Start-ScheduledTask -TaskName "JarvisAssistant"
```

Отключить автозапуск:
```powershell
service\uninstall_autostart.ps1
```

## 4. Логи

Все действия и решения ассистента пишутся в `logs\action.log` (создаётся
автоматически при первом запуске). Смотреть в реальном времени:

```powershell
Get-Content "D:\claude code prj\3\jarvis\logs\action.log" -Wait -Tail 50
```

Если ассистент запущен через автозапуск (без консоли) — это единственный
способ увидеть, что происходит.

## 5. Что ассистент не умеет и не будет уметь (по дизайну)

Удаление файлов, форматирование дисков, выключение/перезагрузка ПК, правка
реестра, деинсталляция ПО, произвольные shell-команды и управление умным
домом — физически отсутствуют в коде (не просто запрещены промптом). Полный
список разрешённых действий — в `spec.md`, сценарии проверки — в
`MANUAL_TEST.md`.
